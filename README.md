# Жуки — курсовая работа

Вариант 5: **«Кампания и прогресс»**. Продолжение Android-приложения из лабораторных работ 1–8.

## Что сделано

Во вкладке «Кампания» находятся три уровня. Игрок проходит их по порядку, а затем может переигрывать любой открытый уровень.

| Уровень | Название | Цель к концу раунда | Время | Скорость | Максимум жуков |
|---|---|---|---|---|---|
| 1 | Разминка | 100 очков | 60 секунд | 40 из 100 | 3 |
| 2 | Быстрые жуки | 200 очков | 60 секунд | 60 из 100 | 5 |
| 3 | Последний рубеж | 300 очков | 60 секунд | 80 из 100 | 7 |

Правила прогресса:

- Новый игрок начинает с первого уровня. Остальные закрыты.
- Уровень пройден, если итоговый счёт не меньше цели. Ровно 100 очков достаточно для первого уровня.
- Следующий уровень открывается после успешного сохранения результата предыдущего.
- Прогресс хранится в Room отдельно для каждого игрока и уровня.
- Запоминается лучший счёт, включая неудачные попытки. Более слабая попытка не уменьшает рекорд и не закрывает уровни.
- Настройки кампании заданы в коде и не зависят от настроек обычной игры.
- В кампании доступны обычные жуки, бонус наклона со звуком и золотой таракан.

## Что сохранено из лабораторных

Регистрация и выбор игроков, знак зодиака, авторы, HTML-правила, настройки обычной игры и рекорды. Обычная игра запускается отдельной кнопкой и не меняет прогресс кампании. Результаты обоих режимов попадают в общую таблицу результатов; вкладка рекордов показывает лучший результат игрока.

Бонус наклона появляется каждые 15 секунд, его эффект длится 5 секунд. Золотой таракан появляется каждые 20 секунд и даёт очки по курсу ЦБ. Сохранены загрузка через Retrofit, кеш курса и виджет на домашнем экране.

При повороте не сбрасываются очки, таймер, жуки, бонусы и ручная пауза. Пока приложение свёрнуто, игровое время не идёт. Это действует и в кампании.

## Как устроен код

Используются уже подключённые Kotlin, Android Views, Room, ViewModel, StateFlow и Koin. Новых библиотек для кампании нет.

| Часть | Файлы и ответственность |
|---|---|
| Правила | `CampaignLevel.kt`: описание трёх уровней, цели и последовательное открытие |
| Хранение | `CampaignProgressEntity.kt`, `CampaignDao.kt`, `CampaignRepositoryImpl.kt`: лучший счёт по паре «игрок + уровень» |
| Обновление БД | `CampaignMigration.kt`: переход с версии 1 на 2 с добавлением таблицы прогресса |
| Выбор уровня | `CampaignFragment.kt`, `fragment_campaign.xml`: загрузка прогресса выбранного игрока, доступные и закрытые уровни |
| Игра | Существующие `GameViewModel`, `GameEngine`, `GameActivity` и `BugsGameView` |
| DI | `AppModule.kt` предоставляет DAO и репозиторий; `GameModule.kt` передаёт репозиторий во ViewModel |

Номер уровня передаётся игровому экрану в Intent и доступен через SavedStateHandle. ViewModel проверяет, открыт ли уровень, и использует параметры из `Campaign`. При окончании раунда сохраняются обычный результат и лучший результат уровня. Если запись не удалась, можно повторить сохранение. Повторная вставка результата того же раунда не создаёт дубликат.

Прогресс не хранится в кнопках или Fragment. После возврата из игры и при повторном открытии приложения он читается из Room. Для закрытых уровней отключены кнопки, а доступ дополнительно проверяется во ViewModel и репозитории.

Миграция создаёт только новую таблицу. Существующие пользователи и результаты не удаляются; `fallbackToDestructiveMigration` не используется.

## Запуск

1. Открыть проект в Android Studio и дождаться синхронизации Gradle.
2. Использовать встроенную JDK Android Studio, установить Android SDK 37.
3. Запустить конфигурацию `app` на эмуляторе или устройстве с Android 7.0/API 24 и новее.
4. Во вкладке регистрации создать игрока или выбрать существующего.
5. Прокрутить строку вкладок до «Кампания», выбрать первый доступный уровень.
6. После раунда дождаться сообщения «Результат сохранён» и вернуться к уровням.

Для сборки и модульных тестов из каталога проекта:

```bash
bash ./gradlew :app:assembleDebug :app:testDebugUnitTest
```

Если в `gradle.properties` задан локальный прокси, который сейчас не запущен, можно отключить его только для этой команды:

```bash
JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' \
bash ./gradlew -Dhttp.proxyHost= -Dhttps.proxyHost= :app:assembleDebug :app:testDebugUnitTest
```

На другом компьютере путь `JAVA_HOME` нужно заменить на свой путь к JDK. В Android Studio для Gradle можно выбрать встроенную JDK.

| `CampaignFlowTest` | Запуск из вкладки, прохождение всех уровней, поворот во время игры, повторное открытие меню, слабую повторную попытку и запрет обхода блокировки |

Запуск Android-тестов на подключённом эмуляторе:

```bash
bash ./gradlew :app:connectedDebugAndroidTest
```

Для отдельного запуска тестов кампании:

```bash
bash ./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.package=com.example.juki.campaign
```

Прежний тест реального сервера ЦБ запускается с аргументом `liveCbr=true`; без него он пропускается. Остальные проверки кампании не требуют сети. В UI-тесте кампании используются управляемые часы, поэтому минутный раунд проверяется без настоящего ожидания минуты; экран, движок и Room работают настоящие.

## Как продемонстрировать

1. Выбрать нового игрока: доступен только первый уровень.
2. Пройти первый уровень и дождаться сохранения: второй станет доступен, третий останется закрытым.
3. Повернуть экран во время следующего раунда: очки, цель, время и объекты остаются.
4. Пройти второй и третий уровни: появится сообщение о завершении кампании.
5. Перезапустить приложение: прогресс остаётся.
6. Переиграть первый уровень с меньшим счётом: лучший результат и открытые уровни сохраняются.
7. Выбрать другого игрока: у него отдельный прогресс, изначально доступен только первый уровень.
8. Запустить обычную игру и показать, что старые функции работают.

## Ограничения

- Кампания локальная, без аккаунтов сервера и синхронизации между телефонами.
- Ровно три заранее заданных уровня. Редактора уровней нет.
- Цель проверяется по итоговому счёту после истечения минуты. Достижение цели в середине раунда не заканчивает его; последующие промахи могут уменьшить счёт ниже цели.
- Запоминается лучший результат уровня. Отдельного списка всех попыток кампании нет; обычные результаты раундов сохраняются в общей таблице.
- После третьего уровня новых уровней нет, доступны повторные прохождения.
- Курс золота зависит от сети и кеша. Без курса золотой таракан не даёт награду, но прохождение возможно на остальных жуках.
- Прогресс завершённых раундов хранится постоянно. Незаконченный раунд восстанавливается через ViewModel/SavedStateHandle в рамках возможностей Android; отдельного сохранения незаконченной партии после любого принудительного завершения приложения нет.
- Удаление данных приложения удаляет игроков, рекорды и прогресс.
